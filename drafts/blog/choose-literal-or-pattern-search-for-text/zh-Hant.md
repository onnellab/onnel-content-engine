# 文字搜尋該選字面搜尋還是模式搜尋

搜尋含有句點的標記，卻找到預期之外的段落，可能是因為輸入的符號被當成規則，而非文字本身。先確認搜尋方式，再考慮把表示式寫得更複雜。

## 問題

什麼時候應該按原樣搜尋文字，什麼時候應該使用模式？

## 簡短回答

查找已知字串時，先用字面搜尋。只有需要以一條規則搜尋多種形式時，才在核對應用程式語法後使用模式搜尋。先用虛構文字測試應符合與不應符合的情況，再於實際文件中只查找、不取代。

## 搜尋詞的兩種含義

字面搜尋查找輸入的字元，不把它們解讀為模式運算子。模式搜尋則把某些字元解讀為規則。正規表示式是模式的一種，但不一定與檔名萬用字元採用同一套語法。

按原樣查找不等於整行符合、整個詞語符合、區分大小寫或檔案位元組完全相同。這些是不同的問題。在長句中找到其中一部分，也可能是字面搜尋的結果。

| 任務 | 建議起點 | 採信結果前檢查 |
| --- | --- | --- |
| 查找寫成 `A.7` 的標記 | 字面搜尋 | 標點與大小寫選項 |
| 查找明確定義的多種形式 | 支援的模式搜尋 | 語法與不需要的結果 |
| 限定要搜尋的檔案 | 檔案範圍設定 | 區分路徑篩選與內文搜尋 |

## 用虛構的小範例測試

建立一份可丟棄的本機筆記，寫入以下三行，不要使用私人資訊或真實文件內容。

```text
A.7
Ax7
A-7
```

如果任務是「查找 `A.7` 這個標記」，預期只有第一行。先用字面搜尋，檢查反白的字元，不要只看結果數量。

在 [RE2 語法](https://github.com/google/re2/wiki/Syntax)中，句點是萬用字元，跳脫後的句點表示符號本身。因此，這個例子中的模式 `A.7` 與 `A\.7` 意圖不同。這不保證使用中的閱讀器支援兩者。字面搜尋時，除非要找反斜線本身，否則不要直接加上它。

通過這個小測試，並不代表規則適合整份文件。例如，`ZA.70` 裡的那一部分是否也算結果，需要另行決定。如果相關，就將它加入測試。

## 建議步驟

1. **用一般文字寫清目標。** 要找一個已知短語，還是多種形式？各寫一個需要的結果和一個相似但要排除的結果。
2. **保留原始內容。** 使用唯讀檢視或獨立的工作副本。測試文字與觀察記錄另外存放，不要將非公開內容上傳至線上模式測試網站。
3. **檢查實際輸入欄位。** 閱讀應用程式說明，核對所選方式、跳脫規則和支援的語法。[Google 說明](https://support.google.com/docs/answer/62754?hl=en)介紹該產品的正規表示式選項與反斜線用法，不能視為所有應用程式的通則。
4. **只查找，不取代。** 在虛構範例中核對每個應符合與應排除的情況。一次只改一個選項。原因不明時，回到較短且有辨識度的字面搜尋。
5. **核對並記錄範圍。** 確認檔案、版本、選取範圍與篩選條件。閱讀前後文，在原始內容之外記錄搜尋詞、模式和相關選項。

## 範圍也會改變結果

[VS Code 文件](https://code.visualstudio.com/docs/editing/codebasics)區分內文搜尋選項與檔案包含、排除用的 glob 模式。不要混用這些欄位。

零筆結果可能代表文字不存在，也可能是選取範圍、篩選條件或搜尋詞有誤。先搜尋一處確定存在的短語。若仍找不到，應先檢查範圍與字元差異，不要不斷擴大模式。留意相似的標點與意外空白，但不要為了方便搜尋就批次正規化原文。

## 結論

選擇能夠表達目標的最簡單方式。找到結果，表示在理解限制的前提下定位到相關文字；它既不能證明已經找齊，也不能作為取代的依據。

## 常見問題

### 字面搜尋需要加上引號嗎？

只有應用程式說明要求時才這樣做。否則，引號本身也可能成為要搜尋的文字。

### 有進階搜尋就支援正規表示式嗎？

不一定。請查閱該欄位的說明。從其他工具複製的模式可能不受支援，也可能有不同含義。

### 測試成功後可以全部取代嗎？

光憑這一點還不夠。取代是獨立的編輯任務，需要可用的備份、實際符合項目的複核，以及變更後的驗證計畫。本流程止於查找與記錄。
