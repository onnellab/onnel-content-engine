Your original video offers English and Korean audio, or perhaps a director's commentary alongside the main soundtrack. After conversion, the video plays, but the audio-language menu has only one choice. The second track may not be broken at all: the converter may simply have left it out. Before converting again, distinguish a missing stream from a stream that is present but not offered or selected by the player.

This guide addresses that specific failure. It explains how to count the actual audio streams, how FFmpeg's default stream selection can omit a language or commentary, and when an explicit stream map can preserve both. The examples are fictional troubleshooting scenarios, not tests of a particular device or application. Keep the original file untouched while investigating.

First ask whether the track is absent or merely hidden

A media file can contain separate video, audio, subtitle and other streams. An audio stream is a distinct track in the file, not just a left or right speaker channel. Two audio streams might carry two languages, while one stereo stream merely has two channels. Confusing those terms makes diagnosis unnecessarily difficult.

Play the original and note which languages or commentary tracks appear in its audio menu. Then examine the output file's audio menu and compare the inventory. A player may have its own preferences, language labels, or decoding limitations, so a missing menu entry alone does not prove that the stream was discarded. Inspect the files themselves before attributing the failure to the conversion.

Use ffprobe to inventory the input and the export

FFmpeg's official ffprobe documentation explains how to display stream information and metadata. If ffprobe is installed, run a command like the one below on a local copy of your input. It reports the stream index, codec type, codec, channel count and any available language or title tags in JSON format. A missing language tag is not proof that the audio track is absent.

ffprobe -v error -show_entries stream=index,codec_type,codec_name,channels:stream_tags=language,title -of json input.mkv

Run the same command with the input.mkv name replaced by your converted output. Make a small inventory: which audio-stream indices appear in the source, which appear in the result, and which language/title tags are actually recorded? The absolute stream indices can change between files; compare track count and content rather than assuming source index 2 will remain index 2 after remuxing.

Why FFmpeg can choose only one audio stream by default

The FFmpeg documentation on stream selection states that, without a manual -map for an output, FFmpeg ordinarily selects one audio stream from the available inputs when the output supports audio. Its automatic choice is based on channel count, with an index tie-breaker. This is not the same as asking which language the viewer prefers. A six-channel commentary can therefore be chosen over a two-channel main track, depending on the actual stream layout.

That behavior explains a particularly confusing result: a conversion may finish without an error and still omit the second spoken language. Choosing an audio encoder with -c:a does not, by itself, instruct FFmpeg to retain every audio stream; stream selection and encoding are separate decisions. Likewise, simply changing a filename extension will not restore an excluded track.

Preserve both audio streams with an explicit map

For a video whose first video stream and every existing audio stream should be retained, the following is an illustrative FFmpeg command. It selects the first video stream from input 0, selects all audio streams from that same input, and requests stream copy to a new Matroska file. The -map 0:a part is the important difference from relying on automatic audio selection.

ffmpeg -i input.mkv -map 0:v:0 -map 0:a -c copy output-with-both-audio.mkv

Use this only after confirming that the source contains the expected streams and that copying their codecs into the intended output container is supported. It does not automatically include subtitles, attachments or additional video streams, and it will fail if a required mapped stream is absent. Chapters follow separate copying rules and may be retained by default, so verify them separately. For a different input layout, map the streams that actually exist rather than copying a command blindly. The FFmpeg format documentation provides container and muxer information relevant to compatibility decisions.

When you need an MP4 rather than a Matroska output, inspect the actual audio and video codec requirements first. An output container may reject a stream even when the original source handled it. In that case, choose a compatible audio conversion method intentionally, without silently dropping the second track. A failed stream-copy attempt is preferable to claiming success from a file that has the wrong soundtrack.

Example 1: a bilingual oral-history interview

Imagine a fictional oral-history recording with a two-channel English narration and a one-channel Korean interpretation. The owner exports a smaller video for an offline archive and discovers that the Korean track is missing. Inspection shows two audio streams in the original file but only one in the export. The channel-count rule makes the English track a plausible automatic selection, although the actual command and files must still be examined.

The editor's first task is not to raise the volume of the Korean voice; that voice is not in the resulting file. They return to the original, explicitly map the required streams to a compatible output, and inspect the exported tracks again. Finally they listen to short passages from each language track in a player that can select between them. A successful JSON inventory establishes presence, not intelligibility or the accuracy of the language labels.

Example 2: surround commentary overtakes the main soundtrack

Imagine a separate fictional student-film archive. Its main soundtrack is stereo, but the optional behind-the-scenes commentary uses six channels. A conversion that relies on automatic audio selection may keep the six-channel stream and discard the stereo main track. Viewers then hear commentary instead of the film's intended sound. This is a selection issue, not necessarily corruption or a mysterious volume setting.

Here the owner writes down the desired output order: main soundtrack first, commentary second. They inspect input indices and explicitly map the two known audio streams in that order, rather than assuming an automatically preferred stream is the desired one. After export, they select each audio option, listen to distinguish them, and verify whether the player's default track selection matches the intended viewer experience. Track order, labels and player behavior should be checked separately.

Verify the final file before replacing anything

  1. Compare stream counts. Run ffprobe on both files and confirm that the required audio streams are present in the output.
  2. Listen to each choice. Use a compatible player to select every output audio track and test the beginning, middle and end of representative speech or music.
  3. Check the right identity. Confirm that English, Korean, commentary or other labels describe what actually plays; a tag is only metadata.
  4. Check the destination. Try the actual target device or app. A track existing in the file does not guarantee that all devices can decode it.
  5. Keep the source. Preserve the original and the conversion settings. Do not replace the only surviving copy merely because the output opens without an error.

If a desired track is present in the converted file but cannot play in the target app, the next problem is compatibility, not stream retention. If only one track remains, return to the mapping configuration before experimenting with unrelated filters. This distinction saves time and keeps a reversible path back to the source.
