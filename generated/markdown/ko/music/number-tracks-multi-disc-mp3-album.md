# 여러 장으로 된 MP3 앨범의 트랙 번호를 매기는 방법

여러 장으로 구성된 음반에는 두 종류의 순서가 동시에 있습니다. 하나는 각 디스크 안에서 곡이 놓인 순서이고, 다른 하나는 전체 세트 안에서 디스크가 놓인 순서입니다. 이 둘을 임의의 연속 번호 하나로 합치면 한 폴더에서는 가지런해 보일 수 있지만 원래 음반의 경계가 사라지고 나중에 오류를 바로잡기 어려워집니다. 안전한 방식은 두 위치를 별도 필드에 기록하고, 불확실한 정보는 억지로 채우지 않으며, 전체 파일을 바꾸기 전에 작은 시험 묶음으로 결과를 확인하는 것입니다.

## 질문

여러 장으로 구성된 MP3 앨범의 트랙 번호를 어떻게 매겨야 하나요?

## 요약 답변

곡이 자기 디스크에서 몇 번째인지 트랙 필드에, 그 디스크가 전체 세트에서 몇 번째인지 디스크 필드에 따로 기록하세요. 예를 들어 세 장짜리 음반의 두 번째 디스크에 있는 네 번째 곡은 트랙 `4`, 디스크 `2`로 나타낼 수 있습니다. 전체 곡 수와 전체 디스크 수를 정확히 확인한 경우에만 `4/11`, `2/3`처럼 전체 수를 덧붙입니다. 원본이 아닌 복사본을 편집하고, 앨범명과 앨범 아티스트 표기를 세트 전체에서 통일한 뒤, 경계에 있는 몇 곡만 저장해서 실제 태그와 목적지 음악 앱의 표시를 모두 확인하세요.

## 트랙 위치와 디스크 위치의 뜻

**트랙 위치**는 이 곡이 현재 디스크에서 몇 번째인지 나타내는 순서를 뜻합니다. ID3v2에서는 `TRCK` 프레임이 이 정보를 담습니다. ID3v2.4 프레임 정의는 현재 위치 뒤에 슬래시와 전체 수를 선택적으로 붙일 수 있도록 설명합니다. 따라서 `4/11`은 열한 곡 중 네 번째라는 뜻이고, 전체 수를 모를 때 `4`만 기록해도 현재 위치 정보는 남습니다.

**디스크 위치**는 “이 디스크가 전체 세트에서 몇 번째인가?”에 답하는 값입니다. `TPOS` 프레임도 현재 위치와 선택적인 전체 수 형식을 사용합니다. `2/3`은 세 부분으로 구성된 세트의 두 번째 부분이라는 뜻입니다. 일반적인 음반에서는 이 부분이 물리적 또는 논리적 디스크인 경우가 많지만, 태그가 모든 음악 앱에서 반드시 “디스크”라는 이름으로 표시된다고 보장하지는 않습니다.

두 필드는 서로 다른 축을 설명합니다. `TRCK=4/11`과 `TPOS=2/3`을 함께 기록하면 “두 번째 디스크의 네 번째 곡”이라는 구조가 보존됩니다. 반대로 이 곡을 단순히 연속 트랙 `15`로만 기록하면 한 가지 청취 순서는 남을 수 있지만 두 번째 디스크가 어디서 시작되는지는 알 수 없습니다. 연속 번호는 개인 보관함의 의도적인 규칙으로 사용할 수 있지만, 발매 음반의 디스크별 위치를 그대로 보존한 것과는 구분해야 합니다.

## 편집 전에 번호 규칙부터 정하세요

먼저 정확한 판본을 설명하는 믿을 수 있는 트랙 목록을 찾으세요. 음반 북클릿, 발매사나 레이블의 공식 목록처럼 디스크 경계와 곡 순서를 분명히 보여 주는 자료가 좋습니다. 같은 제목의 디럭스판, 지역판, 재발매판, 보너스 디스크판은 곡 수가 다를 수 있습니다. 제목이 비슷하다는 이유만으로 다른 판본의 전체 수를 가져오면 정확해 보이는 오류가 생깁니다.

파일을 바꾸기 전에 다음 계획을 짧게 적어 둡니다.

- 세트의 모든 곡에 적용할 정확한 앨범명
- 음반 구성상 필요한 경우 공통으로 사용할 앨범 아티스트 값
- 실제로 보유한 디스크 수와 빠진 디스크가 있는지 여부
- 각 디스크의 곡 수와 보너스 자료가 속한 위치
- 트랙 전체 수와 디스크 전체 수를 확실히 알 수 있는지 여부
- 인쇄된 디스크별 번호를 보존할지, 문서화한 개인 연속 번호를 사용할지 여부

출처가 디스크를 분리해 제시한다면 각 디스크에서 트랙 번호를 다시 1부터 시작하는 방식이 가장 충실한 기본값입니다. 첫 번째 디스크도 1번부터 시작하고 두 번째 디스크도 1번부터 시작하며, `TPOS` 값이 둘을 구분합니다. 모든 칸을 채우기 위해 갖고 있지 않은 디스크나 모르는 전체 수를 만들어 내지 마세요. 확인된 현재 위치만 있는 편이 잘못된 전체 수까지 기록하는 것보다 안전합니다.

## 일괄 편집 전에 필드 대응표를 만드세요

필드 대응표는 변경할 값이 실제 파일에 기록되기 전에 실수를 눈으로 찾게 해 줍니다. 두 장짜리 음반의 경계 표본은 다음처럼 작성할 수 있습니다.

| 파일의 역할 | 트랙 필드 (`TRCK`) | 디스크 필드 (`TPOS`) | 확인할 내용 |
| --- | --- | --- | --- |
| 디스크 1의 첫 곡 | `1/10` | `1/2` | 정확한 판본이며 첫 장이 열 곡인지 확인 |
| 디스크 1의 마지막 곡 | `10/10` | `1/2` | 빠지거나 중복된 위치가 없는지 확인 |
| 디스크 2의 첫 곡 | `1/12` | `2/2` | 번호가 의도적으로 1부터 다시 시작하는지 확인 |
| 디스크 2의 마지막 곡 | `12/12` | `2/2` | 디스크별 곡 수와 전체 장수가 출처와 같은지 확인 |

슬래시 뒤의 전체 수는 필수가 아닙니다. 현재 위치만 확실하다면 `TRCK`에 `1`, `10`, `1`, `12`를 넣고 `TPOS`에 `1` 또는 `2`를 연결하는 것만으로 핵심 구조를 보존할 수 있습니다. 어떤 편집 화면이 자유로운 문자열 입력을 허용하더라도 숫자 위치 필드에 “두 번째 디스크” 같은 문구를 넣지 마세요. 편집기와 목적지의 공식 동작을 확인하기 전에는 별도 메모에 남기는 편이 안전합니다.

## 원본을 보호하고 디스크별로 선택하세요

메타데이터 일괄 편집은 많은 파일을 빠르게 바꾸므로 속도보다 되돌릴 수 있는지가 중요합니다. 음반 전체의 손대지 않은 사본을 작업 폴더 밖에 보관하세요. 저장 공간이 허용되면 파일 목록이나 체크섬도 기록해 작업본과 보존본을 비교할 수 있게 합니다. 편집 대상과 같은 위치에서 함께 덮어쓰이는 복사본은 제대로 분리된 백업이 아닙니다.

공통 값을 적용하기 전에 작업용 복사본을 실제 디스크별로 나눕니다. `CD2`라는 폴더명은 단서일 뿐 증거가 아닙니다. 곡 제목, 재생 시간, 기존 태그, 신뢰할 수 있는 트랙 목록을 함께 비교하세요. 정체를 확신할 수 없는 파일은 일괄 선택에서 빼야 합니다. 불확실성은 편집 범위를 줄여야지 추측을 늘리는 이유가 되어서는 안 됩니다.

정말 같은 값만 묶어서 바꾸세요. 앨범명과 앨범 아티스트는 세트 전체에서 공유할 수 있고, 디스크 위치는 같은 디스크에 속한 선택 범위에서 공유할 수 있습니다. 곡 제목과 트랙 위치는 각 곡마다 다릅니다. 편집기가 명시적인 연속 번호 기능과 검토 가능한 미리보기를 제공하는 경우가 아니라면 곡별 필드를 전체 선택에 덮어쓰지 마세요. 같은 트랙 번호가 모든 파일에 기록되어도 파일 자체는 열리므로 저장 실패보다 발견이 늦을 수 있습니다.

## 권장 워크플로

1. **원본을 보존합니다.** 음반 전체를 별도 작업 위치에 복사하고 원본은 바꾸지 않습니다. 예상한 모든 디스크와 파일이 실제로 있는지 확인합니다.
2. **정확한 판본을 식별합니다.** 곡 제목, 재생 시간, 보너스 자료, 인쇄된 디스크 경계를 믿을 수 있는 목록과 비교합니다. 일치하지 않는 파일은 억지로 순서에 넣지 말고 표시해 둡니다.
3. **디스크별 번호와 연속 번호 중 하나를 선택합니다.** 다중 디스크 발매 구조를 재현한다면 디스크별 트랙 위치와 별도 디스크 필드를 우선합니다. 개인 연속 순서가 꼭 필요하다면 보관함 고유 규칙임을 문서화합니다.
4. **필드 대응표를 작성합니다.** 각 파일의 제목, `TRCK` 현재 위치, 선택적인 곡 전체 수, `TPOS` 현재 위치, 선택적인 디스크 전체 수를 적습니다. 디스크마다 중복과 빈 위치를 확인합니다.
5. **대표 표본만 먼저 편집합니다.** 한 디스크의 첫 곡과 마지막 곡, 다음 디스크의 첫 곡을 포함하세요. 이 세 위치는 끝값, 경계, 번호 재시작 오류를 드러냅니다.
6. **명시적으로 저장한 뒤 다시 엽니다.** 편집기를 닫거나 선택을 해제한 다음 같은 파일을 다시 열어 저장된 값을 봅니다. 저장 전 화면에 보인 값은 파일에 기록됐다는 증거가 아닙니다.
7. **목적지 음악 보관함에서 시험합니다.** 표본만 가져와 앨범 묶음, 디스크 경계, 표시 순서, 디스크 사이 첫 전환을 확인합니다. 이 결과는 해당 앱과 버전에 대한 증거이지 모든 앱의 보편 규칙은 아닙니다.
8. **디스크 단위로 범위를 넓힙니다.** 검토한 대응표의 값만 적용하고, 완료한 디스크마다 첫 곡, 중간 곡 하나, 마지막 곡을 다시 열어 계획과 비교합니다.
9. **두 번째 확인까지 백업을 유지합니다.** 음악 보관함의 공식 새로고침 또는 다시 가져오기 절차를 거친 뒤 전체 음반을 다시 열어 볼 때까지 원본을 보관합니다.

## 화면 정렬만 보지 말고 실제 저장값을 확인하세요

네 종류의 경계를 의도적으로 점검하세요. 각 디스크의 첫 곡, 각 디스크의 마지막 곡, 한 디스크에서 다음 디스크로 넘어가는 지점, 다른 곡 수를 가진 보너스 디스크가 핵심입니다. 중복 위치, 빠진 위치, 파일마다 다른 전체 수, 음반 전체에 잘못 적용된 한 가지 디스크 값도 함께 찾습니다.

재생에 성공했다는 사실을 번호가 정확하다는 증거로 사용하지 마세요. 트랙과 디스크 태그는 오디오를 설명할 뿐 인코딩된 소리를 바꾸지 않습니다. 마찬가지로 태그를 고쳐도 손상된 오디오가 복구되거나 정보가 사실이라고 입증되거나 끊김 없는 재생이 보장되지는 않습니다. 이 문제들은 각각 별도로 확인해야 합니다.

## 자주 생기는 오류와 안전한 대응

| 보이는 증상 | 먼저 살펴볼 데이터 문제 | 안전한 대응 |
| --- | --- | --- |
| 디스크 2가 디스크 1보다 먼저 보임 | 디스크 위치가 없거나 파일마다 다름 | 파일을 다시 열고 `TPOS`를 대응표와 비교함 |
| 서로 다른 디스크의 곡이 섞임 | 디스크 값 누락, 불일치, 또는 목적지의 다른 처리 | 저장 태그를 확인한 뒤 목적지 동작을 문서와 시험으로 확인함 |
| 한 디스크에 같은 트랙 번호가 반복됨 | 공통 트랙 값이 전체 선택에 적용됨 | 영향받은 복사본을 복원하거나 대응표의 곡별 위치를 다시 적용함 |

## 결론

다중 디스크 MP3 트랙 번호를 원래 구조를 잃지 않고 매기려면 트랙 위치와 디스크 위치를 별개의 사실로 다뤄야 합니다. 정확한 판본을 확인하고, 파일마다 대응표를 만든 뒤, 원본을 보존하고, 경계에 있는 소량의 복사본으로 결과를 증명하세요. 전체 수, 앞자리 0, 파일명, 목적지의 표시 방식은 부차적인 규칙입니다. 정확한 `TRCK`와 `TPOS` 위치, 그리고 되돌릴 수 있는 작업 절차가 신뢰할 수 있는 핵심입니다.

## 자주 묻는 질문

### 두 번째 디스크도 트랙 1부터 다시 시작해야 하나요?

각 디스크에 인쇄된 별도 순서를 보존하려는 경우에는 보통 그렇습니다. 다시 시작한 곡 위치는 `TRCK`에 넣고 디스크 차이는 `TPOS`로 구분합니다. 연속 순서도 개인 규칙으로 사용할 수 있지만 그 선택을 기록해 두세요.

### `4/11`이나 `2/3`처럼 전체 수를 꼭 넣어야 하나요?

아닙니다. 전체 수는 선택 사항입니다. 정확한 판본과 전체 구성을 확인했을 때만 넣으세요. 현재 위치가 정확하고 전체 수가 비어 있는 편이 잘못된 전체 수보다 안전합니다.

### 디스크 번호를 넣으면 모든 플레이어에서 올바르게 정렬되나요?

보편적인 동작을 가정할 수 없습니다. 올바른 필드는 데이터를 보존하지만 각 목적지 앱은 그 값을 읽고 묶고 캐시하고 표시하는 방식을 스스로 결정합니다. 사용할 앱에서 대표 복사본을 시험하세요.

### 파일명 번호만으로 트랙과 디스크 태그를 대신할 수 있나요?

파일명은 사람이 폴더를 확인할 때 유용하지만 태그 중심 작업에서 내장 `TRCK`와 `TPOS` 값을 대신하지는 않습니다. 파일명 변경은 메타데이터 작업과 분리하고 되돌릴 수 있게 진행하세요.

### 번호 태그를 바꾸면 음질에 영향이 있나요?

트랙과 디스크 위치는 오디오 샘플이 아니라 메타데이터입니다. 개념적으로 소리를 개선하거나 다시 인코딩하는 작업은 아니지만, 편집기의 실제 저장 결과는 원본 보존과 재확인으로 검증해야 합니다.
