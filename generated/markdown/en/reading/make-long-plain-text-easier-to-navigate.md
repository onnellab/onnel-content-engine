# How to Navigate a Long Plain-Text Document

Scrolling is easy to start and hard to repeat. In a long text document, remembering that a useful passage was “somewhere near the middle” is not enough. A small navigation map can help you return to the right passage without reorganizing the entire file.

## Question

How can I find my way around a long plain-text document without losing my place?

## Short Answer

Keep the original unchanged, make a short map of meaningful sections, and save distinctive phrases you can search for again. Keep an external locator note with the filename, version and surrounding context. Reopen the same file version and confirm each route before relying on it.

## What Makes a Useful Landmark?

A landmark is text or a recorded reference that helps you return to a passage. A distinctive heading can be useful; a heading such as “Notes” repeated twenty times needs more context. Plain text does not, by itself, guarantee a clickable table of contents. A written heading is not necessarily an interactive navigation control.

Wrapped lines on a screen are not reliable source-line numbers. Changing the window width or text size can change wrapping without changing the file.

A locator note is a separate record of a file version and the clues needed to return to a passage.

| Locator | Useful for | Limit to check |
| --- | --- | --- |
| Existing heading | Identifying a section | Repeated headings need context |
| Distinctive phrase | Searching for a passage | Wording may change between versions |
| Line number | Supplementing a reference | Wrapping and edits can change its meaning |

## Recommended Workflow

1. **Preserve the original and choose your mode.** For logs, evidence, or a document you must preserve, use read-only access where available and keep navigation notes separately. If editing is appropriate, work on an identified copy. Do not insert headings into an original merely to make it easier to browse.
2. **Map the existing structure.** Scan for meaningful headings or repeated section markers. In a separate note, list only the sections relevant to your task. Add the filename and a version or date that distinguishes this copy. If there are no headings, describe a passage by its topic and opening words rather than inventing structure inside the source.
3. **Choose and test distinctive search phrases.** Copy a short, recognizable phrase from the passage into your locator note. Search for it and inspect the surrounding text. If there are several matches, add a nearby heading or a second phrase. Check your reader's case, whole-word, or pattern options when results are unexpected; do not assume all search tools behave alike.
4. **Save a route back.** Record the heading, phrase and a brief context note externally. Avoid copying unnecessary confidential text. A locator should help identify the passage, not duplicate the whole document.
5. **Reopen and verify.** Close and reopen the same file version. Test the saved phrase and confirm the surrounding passage. After an edit, import, export or replacement, recheck important locators. Keep old notes labeled with their source version rather than presenting them as current.

## Limits and Optional Tools

Navigation does not establish that a document is accurate or safe to edit. A search hit may be a quotation, an outdated instruction or an unrelated repetition. Read enough context before using it. If a file displays unreadable characters, resolve that interpretation problem before treating a copied phrase as a dependable locator.

## Conclusion

A dependable route back combines a known file version, a useful landmark and a context check. Start with a few important passages and test the map before expanding it.

## FAQ

### Do I need to add headings to the file?

No. Existing headings and external notes may be sufficient. If the original must remain unchanged, do not edit it for navigation.

### What if a phrase appears several times?

Use a more distinctive phrase and check the nearby heading and paragraphs. Do not assume the first match is the right one.

### Will a locator survive every revision?

No. Text and line numbers may change. Keep a version reference and recheck the destination after revisions.
