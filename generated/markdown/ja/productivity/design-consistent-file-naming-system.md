# 探しやすいファイル命名ルールの作り方

## 質問

ファイルが増えても一貫して使える命名ルールは、どう作ればよいですか？

## 短い回答

意味を決めた少数の項目を、毎回同じ順序で並べます。変わりにくい識別子、意味が明確な日付、桁数をそろえた連番、承認状態と分けた改訂番号を使い、短いルールと例を残して実際のファイル5件で試しましょう。

ファイル名にすべての情報を詰め込む必要はありません。一覧で対象を見分け、似たファイルを区別し、必要な順序で探せることが目的です。名前を付けるたびに判断が増えるなら、項目を減らす余地があります。

## 小さな命名ルールを決める

ここでいう「項目」とは、識別子や日付など、1つの意味を担う部分です。命名ルールでは、使う項目、その意味、並べる順序、区切り方を決めます。次は手作業で付ける場合の説明用の例です。特定のアプリでこの組み合わせを作れると示すものではありません。

`atlas_2026-10-05_notes_003_v02.txt`

| 項目 | この例での意味 |
| --- | --- |
| `atlas` | 架空のプロジェクトAtlasの固定識別子 |
| `2026-10-05` | 会議が行われた日、2026年10月5日 |
| `notes` | 文書の種類である会議メモ |
| `003` | この会議のメモ一式の中で使う項目番号003 |
| `v02` | 保存した改訂版の番号02 |
| `.txt` | ファイルの拡張子 |

並びは「プロジェクト_会議日_文書の種類_項目番号_改訂番号」です。番号003は対象を区別し、v02はその対象の改訂版を区別します。この2つを同じ役割として扱わないことが大切です。

## おすすめの手順

1. **普段の探し方に合わせて先頭の項目を選びます。**

   プロジェクトを思い浮かべてから探すなら、プロジェクト名を先頭に置きます。複数のプロジェクトを日付で横断して見るなら、日付を先頭にする方法があります。通常の文字列順では、プロジェクト名が先なら日付順になるのは各プロジェクトの中です。全ファイルがプロジェクトをまたいで日付順になるわけではありません。

2. **日付の書式と意味をセットで決めます。**

   年4桁、月日各2桁の `YYYY-MM-DD` を使います。`2026-10-05` のようにゼロを補い、月と日の順序が曖昧な短い表記を避けます。その日付が開催日、撮影日、発行日などのどれなのかも決めてください。同じ位置に保存日と開催日を混在させないようにします。不明な場合は決めた方法で省略するか、`unknown` などの明文化した表示を使います。今日の日付で穴埋めすると、実際と違う意味になります。

3. **変わりにくい短い識別子を選びます。**

   プロジェクトの略称や記録番号など、対象を継続して指せる情報が向いています。一時的な担当者名や `urgent` のような状況表示は、時間がたつと変わります。似た略称があるなら、先に区別できる形を決めましょう。ファイル名は添付ファイル一覧や共有リンクにも表示されることがあるため、個人情報や機密情報を不用意に入れないでください。

4. **連番を数える範囲と桁数を決めます。**

   プロジェクト全体、会議ごと、処理する一式ごとなど、番号の範囲を明記します。この例の003は、その会議のメモ一式の中の番号です。`001`、`002`、`010` のように桁数をそろえると、単純な文字列順でも並べやすくなります。数字を数値として扱う自然順ソートでは、ゼロがなくても数値順になる場合があります。想定件数に合う桁数を選び、上限を超えた場合は同じ範囲で一貫して桁数を広げる方針を決めます。

5. **改訂番号と承認状態を分けます。**

   `v01` から `v02` に進める条件を短く記録します。たとえば、新しい内容をまとめたレビュー用ファイルを保存するときに番号を上げる方法があります。細かな保存のたびに上げるのか、共有する改訂版ごとなのかを決め、一貫して使いましょう。`v03` は承認済みという意味ではありません。承認は別の合意された状態や記録で確認します。`final-final` という名前も承認の証拠にはなりません。

6. **例外を含む短いルールを書き、5件で試します。**

   項目の順序と意味、区切り文字、省略できる項目、例外の扱いを残します。通常のファイル、別プロジェクトのファイル、番号010の項目、日付不明のファイル、v02の改訂版など、代表例を5件選びます。実際に使うファイル管理アプリや受け渡し先のアプリで、表示、検索、並び順、同名ファイルの有無を確認しましょう。日付を省略した場合に残りの項目を読み違えないかも試します。

## 4つの役割を確認する

![識別子で対象を固定し、日付の意味を定め、連番の桁数をそろえ、改訂番号を付ける4段階](/blog-assets/ja/design-consistent-file-naming-system/workflow-diagram.svg)

1つの項目には1つの意味を持たせます。日付を会議日と保存日で使い分けたり、同じ番号で項目と改訂の両方を表したりすると、読む側に推測が必要になります。

## 守りやすいルールにする

区切り文字は統一します。この例では項目の間にアンダースコア、日付の中にハイフンを使っています。英字を小文字にするのは、この例の編集上の選択です。すべての環境に共通する必須条件ではありません。受け渡し先で使える文字とファイル名の長さも確認してください。

名前を変更するときは拡張子を保ちます。`.txt` を `.pdf` に変えても、ファイル形式は変換されません。また、命名ルールはフォルダー構成、アクセス権、変更履歴の代わりにはなりません。それぞれ別に管理する必要があります。

ルールを変更しても、過去の保管ファイルを一括で自動改名しないようにします。リンクや他の人の作業に影響する可能性があるためです。新しいファイルから適用するのか、確認した一部だけを変更するのか、先に範囲を決めましょう。

## まとめ

少ない項目を固定した順序で使い、それぞれの意味を説明できるようにしましょう。日付、番号の範囲、改訂の条件を決め、実際のファイル5件で確認します。迷う場面があれば、項目を増やす前にルールを簡単にできないか見直してください。

## よくある質問

### すべてのファイルに日付が必要ですか？

いいえ。検索や区別に役立つ場合だけ付けます。付ける場合は何の日付かを定め、不明な日付を今日の日付で置き換えないようにします。

### 日付とプロジェクトのどちらを先にしますか？

主な探し方に合わせます。日付順で横断的に見るなら日付、プロジェクトごとにまとめたいならプロジェクトを先にします。プロジェクトが先の場合、日付順になるのは各プロジェクトの中です。

### v03は承認済みという意味ですか？

いいえ。決めたルールに沿った改訂番号です。承認は、別の状態や記録で確認する必要があります。

### Alignaで例とまったく同じ形式を作れますか？

確認されているのは8種類の固定プリセットです。この記事の組み合わせ全体を再現できるとは確認されていません。目的に合うプリセットがあるか調べ、適用前にプレビューを確認してください。
