# 替换原文件前，如何检查转换后的媒体文件

转换完成，新文件也能打开。这是个好的开始，但还不能说明结尾完整、所需音频都在，或接收文件的应用能正确处理它。在替换日常使用的文件之前，要分别检查这些问题，并保留恢复原文件的办法。

## 问题

替换原文件之前，应该怎样检查转换后的媒体文件？

## 简短回答

保留原文件，检查导出文件，在实际使用的应用中播放有代表性的片段，并核对所需轨道和元数据。确认差异的原因后，再决定是否接受转换结果。抽查通过，也不代表可以删除唯一的原文件。

## 先明确合格结果必须保留什么

**验收检查**是指将输出文件与事先为其用途列出的要求逐项比较。它并不保证新文件与源文件完全相同。

记下源文件名、输出文件名、计划使用的应用或设备，以及必须保留的内容。对于录音，要求可能包括开头和结尾说的话、清晰可辨的语音，以及所需声道。对于视频，要检查画面、声音及两者是否同步。如果字幕、章节、封面或标签很重要，也要列入清单，不要默认转换时会保留。

区分有意的改变和真正的问题。从视频中提取音频，本来就会去掉画面。只有在预期结果仍是视频时，画面缺失才是问题。本指南从转换完成后开始；如果尚未确定目标格式，请先阅读下方的相关指南。

## 三种检查回答不同的问题

| 检查方式 | 能提供的有效信息 | 无法证明的事项 |
| --- | --- | --- |
| 查看文件属性 | 时长、数据流和现有元数据是否符合要求 | 每一段都能正确播放 |
| 在实际使用环境中播放 | 接收文件的应用能否处理已测试的片段 | 未测试的片段或另一台设备也能正常使用 |
| 核验备份校验和 | 复制文件是否与记录的字节指纹一致 | 转换后的声音或画面是否正确 |

**数据流**是指文件中独立的媒体组成部分，例如音轨或视频轨道。文件信息工具可以列出这些组成部分。[FFmpeg ffprobe 文档](https://ffmpeg.org/ffprobe.html)介绍了如何查看容器、数据流和标签。如果转换工具不提供这些详情，请使用单独的检查工具；文件信息报告不能代替试听或观看。

## 推荐流程

1. **单独保留源文件。** 将源文件和输出文件放在不同文件夹中，或使用容易区分的文件名。记录转换的是哪个文件。检查期间，不要覆盖唯一的源文件，也不要让清理操作将其删除。
2. **打开实际导出的文件。** 在文件管理器中找到它，确认文件名和路径。转换工具中的预览，或播放器媒体库中的旧条目，可能指向其他文件。记下转换工具和播放器的版本，方便复现检查过程。
3. **比较重要属性。** 检查大致时长、预期的音视频轨道、声道信息、视频画面尺寸，以及任何必须保留的标签。文件大小本身不能衡量质量。时长差异明显时，需要查明原因；细微差异可能来自工具的显示方式或格式特性，因此也要实际比较开头和结尾。
4. **播放有代表性的片段。** 试听或观看开头、中间和结尾。选入文件中的轻声说话、较响的片段、场景切换或其他对转换效果要求较高的内容。尝试向前和向后跳转播放位置。检查视频时，观察能看见说话动作或撞击瞬间的片段，判断声音是否对齐；检查音频时，留意内容缺失、失真和意外的静音。
5. **使用真正的目标环境。** 将输出文件导入计划使用的播放器、编辑器或设备。如有相关要求，在那里测试轨道选择和字幕。如果文件适合上传，且所用服务会处理上传内容，也要检查服务处理后的结果。在转换工具中检查通过，不能代替这一步。
6. **记录结果，并保留可用于恢复的副本。** 记下输出文件、使用环境、检查过的片段，以及检查的局限。重要且无法重录的录音或录像值得完整试听或观看；抽查总会留下未检查的区间。在独立存储位置保留原文件备份，并在整理工作文件之前确认能够取回备份。

## 用简单的检查记录定位问题

以下是假设示例，并非应用或设备测试：一份采访录音导出后，开头清晰，却少了最后一句话。记下源文件名和输出文件名、问题的大致位置，以及源文件中的同一段能否播放。排查期间保留两个文件。“这个输出文件缺少最后一句话”比“转换质量不好”更有助于定位问题。

| 观察到的现象 | 下一步检查 |
| --- | --- |
| 输出文件过早结束 | 对比源文件结尾，再确认打开的是最新导出的文件 |
| 视频没有可听见的声音 | 检查源文件音频、输出文件音轨、播放器是否静音，以及当前选择的轨道 |
| 声音与画面逐渐不同步 | 在源文件和目标使用环境中，对比靠前和靠后的两个事件 |
| 标签或封面缺失 | 单独查看输出文件中的字段，不要只看播放器的显示内容 |
| 一个播放器能播放，另一个不能 | 记录目标使用环境，查看其支持的输入格式，再决定是否重新转换 |

如果工具允许，每次只调整一个相关设置或更换一种转换方法。从原文件重新导出，再重复之前未通过的检查和基本播放检查。反复转换有损输出文件，无法修复原始内容细节的缺失。

## 校验和能证明什么，不能证明什么

校验和是根据文件字节计算出的值。[GNU SHA-2 工具](https://www.gnu.org/s/coreutils/manual/html_node/sha2-utilities.html)等工具可以计算和核验这些值。可以比较保存的原文件与其备份，或比较已验收的输出文件与该输出文件的副本。比较时，两份文件必须使用同一种算法，例如都使用 SHA-256。在此前提下，校验值发生变化，说明字节层面存在需要调查的差异。

不要期待原文件和转换后的衍生文件具有相同的校验和，它们的字节通常不同。备份校验和一致，可以支持对副本完整性的判断；它不能判断声音或画面是否合格、所选内容是否完整，也不能判断文件是否适合目标使用环境。

## 结论

检查转换后的媒体文件时，先按一份简短的要求清单进行比较，查看文件信息，再到计划使用的环境中播放。记录检查过什么，以及哪些部分尚未检查。接受一份用于交付的副本，与决定如何归档原文件，是两个不同的决定；如果丢失原文件会造成较大损失，就应保留它。

## 常见问题

### 文件能打开就够了吗？

不够。打开文件并不能检查结尾、全部轨道或每个片段。还需要核对必要属性，并播放重要内容。

### 时长必须完全相同吗？

不一定。显示时的取整和格式特性可能造成细微差异。应调查内容缺失或明显的时长不符，不要依赖适用于所有文件的统一时差标准。

### 文件更小就意味着转换更差吗？

仅凭大小无法判断。应结合预期用途、必须保留的内容和实际播放效果来评估。

### 抽查通过后，可以删除原文件吗？

抽查会留下未检查的部分。请保留可取回的原文件备份，尤其是无法替代的录音录像，或日后可能再次编辑的素材。
