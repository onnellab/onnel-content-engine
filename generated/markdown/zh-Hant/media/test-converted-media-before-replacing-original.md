# 取代原始檔案前，如何檢查轉檔後的媒體檔案

轉檔完成，新檔案也能開啟。這是個好的開始，但還無法確認結尾是否完整、需要的音訊是否都在，或接收檔案的應用程式能否正確處理它。在替換平常使用的檔案前，請分別檢查這些問題，並保留回復原始檔案的途徑。

## 問題

取代原始檔案之前，應該如何檢查轉檔後的媒體檔案？

## 簡短回答

保留原始檔案，檢查匯出檔案，在實際使用的應用程式中播放具代表性的片段，並確認必要的軌道與中繼資料。先釐清差異，再決定是否接受轉檔結果。抽樣檢查通過，也不代表可以刪除唯一的原始檔案。

## 先訂出合格結果必須保留的內容

**驗收檢查**是指將輸出檔案與事先針對其用途列出的要求逐項比較。這並不保證新檔案與來源檔案完全相同。

記下來源檔名、輸出檔名、預計使用的應用程式或裝置，以及必須保留的內容。以錄音來說，可能包括開頭與結尾說的話、清楚可辨的語音，以及必要的聲道。影片則要檢查影像、聲音及兩者是否同步。如果字幕、章節、封面圖或標籤很重要，也要列入清單，不要預設轉檔時會一併保留。

請區分預期中的改變和真正的問題。從影片擷取音訊，本來就會移除影像。只有在預期結果仍是影片的情況下，影像不見才是問題。本指南從轉檔完成後開始；如果還沒決定目標格式，請先閱讀下方的相關指南。

## 三種檢查各自回答不同問題

| 檢查方式 | 能提供的有效資訊 | 無法確認的事項 |
| --- | --- | --- |
| 查看檔案內容資訊 | 時長、串流及現有中繼資料是否符合要求 | 每一段都能正確播放 |
| 在實際使用環境中播放 | 接收檔案的應用程式能否處理已測試的片段 | 未測試的片段或其他裝置也能正常使用 |
| 驗證備份檢查碼 | 複製的檔案是否與記錄的位元組指紋一致 | 轉檔後的聲音或影像是否正確 |

**串流**是指檔案中個別的媒體組成部分，例如音軌或視訊軌道。檔案資訊工具可以列出這些組成部分。[FFmpeg ffprobe 文件](https://ffmpeg.org/ffprobe.html)說明了容器、串流與標籤的檢查方式。如果轉檔工具未提供這些細節，請另外使用檢查工具；檔案資訊報告不能取代試聽或觀看。

## 建議流程

1. **另外保留來源檔案。** 將來源檔案與輸出檔案放在不同資料夾，或使用容易辨識的檔名。記錄實際轉換的是哪個檔案。檢查期間，請勿覆寫唯一的來源檔案，也不要讓清理操作將它刪除。
2. **開啟實際匯出的檔案。** 在檔案管理員中找到它，確認檔名與路徑。轉檔工具的預覽畫面，或播放器媒體庫中的舊項目，可能指向另一個檔案。記下轉檔工具與播放器的版本，方便重現檢查過程。
3. **比對重要的檔案資訊。** 檢查大致時長、預期的音訊與視訊軌道、聲道資訊、影片畫面尺寸，以及必須保留的標籤。光看檔案大小，無法衡量品質。時長差異明顯時，應查明原因；些微差異可能來自工具的顯示方式或格式特性，因此也要實際比對開頭和結尾。
4. **播放具代表性的片段。** 試聽或觀看開頭、中段與結尾。納入檔案中的輕聲說話、較大聲的片段、場景切換，或其他較容易暴露轉檔問題的內容。試著向前與向後跳轉播放位置。檢查影片時，觀察看得見說話動作或碰撞瞬間的片段，判斷聲音是否對齊；檢查音訊時，留意內容遺漏、失真與非預期的靜音。
5. **到真正的使用環境測試。** 將輸出檔案匯入預計使用的播放器、編輯器或裝置。如果有相關需求，請在該環境中測試軌道切換與字幕。若檔案適合上傳，且該服務會處理上傳內容，也要檢查服務處理後的結果。在轉檔工具中檢查通過，不能取代這一步。
6. **記錄結果，並保留可用來復原的副本。** 記下輸出檔案、使用環境、檢查過的片段，以及檢查的限制。重要且無法重錄的錄音或影片，值得從頭到尾完整試聽或觀看；抽樣檢查仍會留下未檢查的區段。在獨立儲存位置保留原始檔案備份，並在整理工作用檔案前，確認能夠取回備份。

## 用簡單的檢查紀錄找出問題

以下是假設情境，並非應用程式或裝置測試：一份訪談錄音匯出後，開頭很清楚，最後一句話卻不見了。記下來源與輸出檔名、問題發生的大致位置，以及來源檔案的同一片段能否播放。釐清原因前，請保留兩個檔案。「這個輸出檔少了最後一句話」比「轉檔品質不好」更有助於找出問題。

| 觀察到的現象 | 下一步檢查 |
| --- | --- |
| 輸出檔案提早結束 | 比對來源檔案的結尾，再確認開啟的是最新匯出的檔案 |
| 影片聽不到聲音 | 檢查來源音訊、輸出檔音軌、播放器是否靜音，以及目前選取的軌道 |
| 聲音與影像逐漸不同步 | 在來源檔案與目標使用環境中，比對前段與後段的兩個事件 |
| 標籤或封面圖遺失 | 另行檢查輸出檔案中的欄位，不要只看播放器顯示的內容 |
| 某個播放器能播放，另一個卻不行 | 記錄目標使用環境，查看它支援的輸入格式，再決定是否重新轉檔 |

若工具允許，每次只調整一項相關設定，或改用一種轉檔方式。從原始檔重新匯出，再重做先前未通過的檢查與基本播放檢查。反覆轉換有損格式的輸出檔，無法補回遺失的原始內容細節。

## 檢查碼能證明什麼，又不能證明什麼

檢查碼是根據檔案位元組計算出的數值。[GNU SHA-2 工具](https://www.gnu.org/s/coreutils/manual/html_node/sha2-utilities.html)等工具可以計算及驗證這類數值。可以比對保存的原始檔與備份，或比對已驗收的輸出檔與同一輸出檔的副本。比對時，兩份檔案必須使用同一種演算法，例如都使用 SHA-256。在此前提下，數值改變，表示位元組層級出現需要釐清的差異。

不要預期原始檔與轉檔後的衍生檔案會有相同的檢查碼，兩者的位元組通常不同。備份檢查碼相符，可作為確認副本完整性的依據；它無法判斷聲音或影像是否符合要求、所選內容是否完整，也無法判斷檔案是否適合目標使用環境。

## 結論

檢查轉檔後的媒體檔案時，先依一份簡短的需求清單比對，查看檔案資訊，再到預計使用的環境中播放。記錄已檢查的項目，以及尚未檢查的部分。接受一份交付用副本，與決定如何封存原始檔，是兩件不同的事；如果遺失原始檔會造成重大損失，就應該保留。

## 常見問題

### 檔案能開啟就夠了嗎？

不夠。開啟檔案並未檢查結尾、所有軌道或每個片段。還要確認必要的檔案資訊，並播放重要內容。

### 時長必須完全相同嗎？

不一定。顯示時的取整與格式特性，可能造成些微差異。應查明內容遺漏或明顯時長不符的原因，不要依賴適用於所有檔案的統一秒數容許值。

### 檔案比較小，就代表轉檔品質比較差嗎？

光看大小無法判斷。請根據預定用途、必要內容與實際播放結果來評估。

### 抽樣檢查通過後，可以刪除原始檔嗎？

抽樣檢查會留下未檢查的部分。請保留可取回的原始檔備份，尤其是無可取代的錄音或影片，以及日後可能再次編輯的素材。
