# 如何整理可重複使用的文字片段

儲存好的回覆能減少重複輸入，卻也可能夾帶舊日期、不合適的語氣，或對另一個人作出的承諾。可重複使用的文字片段需要保留適用條件，即使忘記原本的對話，也能判斷何時使用。

## 問題

如何重複使用經常輸入的文字，同時保留確保內容正確所需的情境？

## 簡短回答

只儲存固定不變的表述，標示每次要修改的資訊，並另外記錄適用情境。傳送前確認收件人、替換所有預留位置，再讀過完整訊息。依據改變時，也要重新檢查儲存的文字。

## 區分固定表述與變動資訊

**文字片段**是指為了日後重複使用而儲存的一小段文字。**預留位置**是標示每次需要填入資訊的明顯記號，例如[日期]或[連結]。儲存文字或加上記號，都不代表回覆已經可以直接傳送。

把要傳送的正文與個人使用備註分開。備註可以記錄用途、適用對象、資訊依據及最後檢查日期。如果工具沒有獨立備註欄，就在另一份文件中保存這些說明。不要把標籤或預留位置當成 App 必然提供的功能。

| 可以保留在常用文字中的內容 | 每次需要檢查的內容 |
| --- | --- |
| 中性的資料請求表述 | 收件人及實際需要的資訊 |
| 依據仍然有效的說明 | 是否適用於目前情況 |
| 明顯的[連結]記號 | 正確的目標網址及有權存取的人 |

不要在一般文字片段中儲存密碼、一次性驗證碼或不必要的私人資訊。複製過來的客戶姓名或帳號資料，可能混入下一次對話。

## 建議工作流程

1. **選擇一種重複任務。** 從少量確實經常使用、風險較低的回覆開始。只留下在這些情況中都成立的句子。
2. **移除個案資訊。** 用明顯記號替換日期、姓名和連結。除非準備每次確認，否則不要保留承諾、價格或例外情況。
3. **記錄適用情境。** 在獨立備註中說明適合哪些對象、什麼情況不宜使用。如果表述依賴政策或指示，附上權威來源連結。
4. **先整理文字，再貼上。** 先刪除個人使用備註和不必要的私人資訊，再複製到實際目標位置。接著檢查尚未傳送草稿中的換行、連結和語氣，並替換所有記號。即使尚未傳送，目標 App 也可能儲存或同步草稿。
5. **傳送前讀過全文。** 確認收件人、最新資訊及請求事項。可以搜尋左方括號來尋找所選記號，然後再次閱讀；搜尋無法找出所有錯誤。
6. **維護文字集合。** 資訊來源改變時，重新檢查相關片段。清理過時副本，比較不同使用情境後，再合併真正重複的內容。

## 一個小例子

這是日常資料請求的假設範例：「請最晚於[日期]，透過[連結]傳送[文件]。」個人備註註明，只有截止時間和提交位置已經談妥時才能使用。傳送前確認對方能夠開啟連結，而且提出這項資料請求是合宜的。一句方便的範本不會賦予你索取或分享資訊的權限。

## 結論

實用的常用文字應同時保留措辭與適用條件。從少量內容開始，清楚標示變動資訊。每次貼上後，都先把訊息當作草稿，直到確認它適用於新的情境。

## 常見問題

### 可以儲存整則舊回覆嗎？

先刪除只屬於原對話的資訊和承諾。只保留較短的可重複使用部分，通常更容易檢查。

### 預留位置會自動填入嗎？

本流程需要手動替換。即使某個工具明確提供自動填入功能，也要檢查結果。

### 應該多久檢查一次？

基礎資訊改變，或重複使用的回覆顯得過時時，就應檢查。依照使用頻率選擇適合自己的維護習慣。

### 在本機儲存就足以保護貼上的訊息嗎？

不夠。分享前需要檢查目標、收件人及內容；接收資訊的 App 或服務有自己的資料處理方式。
